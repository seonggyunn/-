# 운영자 업무 안내

## 무료 진단
신청이 저장되면 고유 접수번호·진단 업무·동의3종·알림 outbox가 생성된다. 로컬 알림은 미발송 미리보기다. `신청·고객`에서 검색·상태 필터를 쓰고 고객 상세에서 담당자·기한·내부 메모를 기록한다. 공개 문의 원문은 내부 메모와 별도로 유지한다.

## 상태와 진단
NEW→DIAGNOSING→PROPOSAL_READY→AWAITING_APPROVAL→APPROVED→IN_PROGRESS→VERIFYING→COMPLETED를 기본으로 한다. 보류·거절·취소·보완 전이는 서버가 허용 여부를 검증한다. 완료를 무조건 누를 수 있는 도구가 아니다. 확인 완료 진단에는 원문URL·증빙을 넣고, 확인하지 못한 정보는 확인불가/고객확인필요로 남긴다.

## 변경과 승인
네이버/구글·항목·기존값·제안값·이유·증빙으로 변경안을 만든다. 승인 요청 알림을 준비해도 승인된 것은 아니다. 담당자는 고객이 실제 사업장 관리 권한을 가진 사람인지 확인한 뒤 승인자·권한증빙·동의문안버전을 기록한다. 이메일 주소를 가지고 있다는 사실만으로 승인 처리하지 않는다.

현재 수동 제공자는 공식 관리화면에서 작업할 절차를 안내한다. `수동 실행 증빙 기록`은 플랫폼을 실제 변경하는 버튼이 아니다. 담당자가 허용된 관리 화면에서 작업하고 결과증빙을 기록한 뒤, 재확인 증빙도 남겨야 완료로 진행할 수 있다. API 검증이라고 표시하지 않는다. 승인은 철회할 수 있으며 과거 기록을 지우지 않는다.

## 보고서와 후속 작업
진단 기록이 있으면 버전별 보고서를 만든다. PDF는 사전 설치한 Chromium과 Noto CJK로 생성한다. PDF 작업은 영속 큐에서 처리하거나 인증 다운로드 시 생성·저장한다. lead 완료 시 보고서 작업과 후속 검토 업무가 자동 생성된다. 보고서가 준비되면 고객 알림이 outbox에 추가된다. 고객 공개 포털은 아직 없으므로 담당자가 합의한 안전한 채널로 PDF를 전달한다. 관리자 링크를 고객에게 공개 링크처럼 보내지 않는다.

## 계약과 월간 운영
고객 전환 기록과 입금은 다르다. 관리자는 계약근거·서비스·주기·금액·활성상태·직접확인한입금상태를 기록한다. MRR은 활성 월계약의 기록 금액이며 현금 수금 합계가 아니다. 월간 worker가 기한이 된 계약의 점검 업무를 고유키로 생성하고 다음 기한으로 이동한다. 소급 계약은 다음 실행 때 남은 기한을 순서대로 처리한다.

## 알림·실패
환경변수가 없으면 PREVIEW. 연결 후 신규 알림은 PENDING이며 worker가 처리한다. 기존 미리보기는 관리자가 발송 대기로 전환할 수 있다. 실패가 확실한 FAILED만 명시적으로 재시도한다. SENDING/UNKNOWN은 제공자 기록 확인 전 상태를 바꿔 재발송하지 않는다. 연락 철회는 고객 상세에서 기록하고 대기 중 고객 알림을 중단한다. 한도는 조직별 하루10시도이며 마케팅 대량발송 기능은 없다.

## 초안
AI 키가 없으면 로컬 템플릿이 작동한다. 입력과 출력을 볼 수 있고 수정할 수 있다. 입력에 불필요한 개인정보를 포함하지 않는다. 생성 결과는 확인된 사실이 아니며 고객 승인 없이 게시하지 않는다. AI 버튼은 외부 게시 버튼이 아니다.
