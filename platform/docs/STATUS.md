# 구현 상태와 자동화 범위

| 영역 | 구현·로컬 검증 | 외부 운영 상태 |
|---|---|---|
| 공개 사이트·진단 폼·접수번호 | 실제 저장·동의·중복방지 | 공개 호스팅 계정 미연결 |
| 로그인·역할·CRM·CSV | 서버인증·조직격리 검증 | 실제 고객 미입력 |
| 업무·진단·승인·철회 | 상태·증빙·이력 실제 DB 저장 | 고객 권한 확인은 운영자 책임 |
| 네이버·구글 | 수동 작업절차·결과증빙·재확인 | 직접 API 변경 비활성 |
| AI 도우미 | 편집 가능한 템플릿, 출력검증 어댑터 | 실제 AI 키·제공자 호출 미검증 |
| 보고서·PDF·증빙 | 한글 PDF·사설 파일·인증다운로드 | 고객에게 전달할 포털은 후속 단계 |
| 알림·스케줄 | 아웃박스·PDF작업·월간/기한업무 | 실제 발신주소/API 키 미연결 |
| 계약·MRR | 수동계약·입금상태·월간업무 | PG/자동입금 확인 미연결 |
| 데이터베이스 | SQLite와 실제 로컬PostgreSQL 검증 | Supabase 프로젝트 미연결 |
| 배포 | 프로덕션 번들과 Docker 검증 | 운영 도메인·HTTPS·공개배포 미검증 |

## 실제 자동화
1. 신청→검증→접수번호→동의 저장→진단업무→알림대기.
2. 완료→보고서버전→PDF작업→비공개저장→알림대기→후속검토업무.
3. 활성 월계약→기한 점검업무→다음 기한. 기한초과 알림은 일별 중복 방지.
4. 알림제공자가설정된환경에서만worker가발송한다. 로컬 PREVIEW는 발송이 아니다.
5. 플랫폼조회·수정·고객사업장권한확인·최종검수·수금은자동성공처리하지않는다.

## 우선순위별 남은 작업
1. 본인 소유 배포계정과 공개도메인/HTTPS·지속저장소를 연결하고 실제신청·로그인·PDF smoke test.
2. 운영 Supabase/PostgreSQL 연결·마이그레이션·백업복구·정식운영자계정 확인.
3. 검증된 메일발신주소와 제공자연결→본인테스트주소→실제전달·실패·중복방지 확인.
4. 고객 관리권한·위임/승인문안·보관/삭제·정산 조건을 실제업무에맞게 검토.
5. Google Business Profile의 공식 API 접근승인·OAuth·사업장별권한을 받은 뒤 별도 어댑터 구현·검증. 네이버는 공식지원 확인 전 수동유지.
6. 고객포털·MFA·파일악성코드검사·모니터링·대규모큐/다중인스턴스는 수요에 따라 후속 개발.

유료 인프라·도메인·구독을 구입하지 않았다. 실제 고객실적·외부 프로필 변경·메일 도착·수금은 이 개발 테스트로 입증되지 않는다.
